## 1. 背景与目标

### 1.1 背景

Signalix 是一个 **本地化量化交易引擎**：Go 负责行情、路由、决策、执行、风控与生命周期；Python 负责策略逻辑；交易所侧一期以 **Gate.io 永续** 为主，并通过 `pkg/exchange/perp` 抽象支持后续扩展。

### 1.2 产品目标

1. **可长期运行**：持久化、启动对账、进程隔离；断线后可恢复。
2. **无 UI 内核**：本仓库不承载界面；远程操作经 **gRPC**（及后续独立 HTTP 网关）完成。
3. **边界清晰**：引擎持有交易所密钥与交易真相；网关（若部署）负责认证、限流与 REST 语义。
4. **可开源协作**：默认配置与文档不绑定个人密钥；README 保留安全与免责声明。

### 1.3 非目标（当前阶段明确不做）

- 本仓库内实现 Web / App / TUI。
- 多租户 SaaS、商业化计费、托管客户资金。
- 高频做市、微秒级延迟（不与专业 HFT 基础设施对标）。

## 2. 产品定位与系统边界

```
┌─────────────────────────────────────────────────────────────┐
│  UI / 自动化客户端（独立项目，可选）                            │
└───────────────────────────┬─────────────────────────────────┘
                            │ HTTPS (+ 可选 WSS)
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  HTTP 网关（后续独立仓库或子模块，当前未实现）                   │
│  认证、限流、REST/WebSocket、审计                              │
└───────────────────────────┬─────────────────────────────────┘
                            │ gRPC（已实现，可选启用）
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Signalix 引擎（本仓库）                                       │
│  行情路由、策略进程、决策、风控、OMS、投影、持久化、对账          │
└───────────────────────────┬─────────────────────────────────┘
                            │
                            ▼
                     Gate.io 永续（一期）
```

**职责划分**

| 层级 | 职责 | 不负责 |
|------|------|--------|
| **引擎** | 交易真相、风控、下单、订单状态机、策略生命周期、所侧适配 | HTTP 路由、CORS、面向浏览器的鉴权 |
| **网关** | HTTP API、认证、限流、REST↔gRPC 映射 | 策略逻辑、直连所 API 下单 |
| **UI** | 展示与交互 | 直连交易所密钥（推荐密钥仅配置在引擎侧） |

## 3. 用户与典型场景

### 3.1 用户画像

| 角色 | 说明 |
|------|------|
| **Operator** | 部署引擎、配置策略与风控、启停、紧急处置。 |
| **Strategy Author** | 编写 Python 策略，使用 SDK 与 IPC / RPC。 |
| **Integrator** | 通过 gRPC（或未来网关 REST）集成监控与自动化。 |

### 3.2 核心场景

1. **日常运行**：启动 `signalixd`；查看策略状态、持仓、订单（CLI / gRPC / 未来网关）。
2. **策略迭代**：更新策略目录；重载 catalog 或启停单策略。
3. **异常处置**：断线、拒单、风控触发；撤单 / 平仓（经引擎或 gRPC）。
4. **维护窗口**：优雅停机、SQLite 刷盘、升级后通过对账恢复。

---

## 4. 设计原则

1. **单一真相源**：订单与持仓以引擎 OMS + 账户投影 + 所侧对账为准。
2. **Fail-safe**：默认偏保守；订单路径禁止静默丢弃（可观测 Warn / 阻塞策略）。
3. **可观测优先**：`trace_id` 贯穿 tick → signal → order；结构化日志。
4. **API 稳定**：gRPC 包 `signalix.engine.v1`；网关未来对外 `v1` REST 前缀。
5. **引擎可测**：domain 单测 + fake exchange 集成测试。

## 6. 功能模块 — 网关层（后续）

网关 **不实现策略与直连交易所下单**；仅转发、聚合、鉴权与限流。当前 **未在本仓库实现**。

| 分组 | 示例能力 | 引擎对应 |
|------|----------|----------|
| System | 健康、版本 | gRPC Ping / GetEngineInfo |
| Strategies | 启停、列表 | StartStrategy / ListStrategies |
| Orders | 查单、撤单 | GetOrder / CancelOrder / 事件流 |
| Positions | 持仓汇总 | AccountProjection |
| Emergency | Kill Switch | 已实现 |

## 7. 引擎对外集成

### 7.1 gRPC（已实现，可选）

契约：`api/proto/signalix/engine/v1`。默认 `127.0.0.1` 监听；metadata `x-request-id` 透传日志。详见 [ARCHITECTURE.md](./ARCHITECTURE.md) §6。

### 7.2 HTTP 网关（后续）

独立 OpenAPI `v1`；网关持引擎调用 Token，**不持所 API Secret**（推荐）。

## 10. 风险与开放问题

1. **密钥管理**：仅引擎进程读取本地配置或环境变量。
2. **公网暴露**：若远程访问 gRPC / 网关，须 mTLS 或强 Token + 防火墙。
3. **开源配置**：仓库提供 `config.example.toml`；勿提交真实密钥。
4. **法律责任**：不构成投资建议；使用者自担交易风险。
